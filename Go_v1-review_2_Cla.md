# Go v1 review 2

Reading through this, I think it's a fun exercise but the mathematical rigor is very uneven across sections — some parts are genuinely sound, others are decoration where an algebraic formalism gets bolted onto a Go concept without doing any real work. Here's my honest section-by-section take.

**§2, the $\mathbb{F}_3$ board — mostly cosmetic.** Relabeling $\{empty, black, white\}$ as $\{0,1,2\}\subset\mathbb{F}_3$ is fine as notation, but the vector-space structure never actually gets used for anything except negation (the color swap). There's no natural "addition" of two board positions in Go, so the module/vector-space structure doesn't buy you theorems the way it would in, say, coding theory. The claim that legality is "automatically satisfied... since $1\neq 2$" is close to vacuous: you're encoding one value per intersection by construction, so of course no intersection holds two colors — that's not a consequence of working over $\mathbb{F}_3$, it's just how a function into a 3-element set works. The real legality constraints (suicide, ko, liberties) aren't touched by this structure at all.

**§3, category/groupoid — the groupoid claim doesn't hold up.** The category framing of a game tree (positions as objects, move-sequences as morphisms) is completely generic — it works for any deterministic game and isn't really Go-specific. The groupoid claim is the weak point: a "reversible" morphism would need a legal move sequence that undoes a placement, but Go has no move that removes a stone except by capture, and capture isn't the opponent voluntarily undoing your move. So the "reversible core" $\mathbf{G}_n$ is essentially trivial (just identities), not a rich substructure. Calling ko a "congruence" is also asserted rather than constructed — positional superko is a history-dependent constraint, and turning that into a precise equivalence relation on morphisms is nontrivial and isn't actually done here.

**§4, homology of liberties — this one has an actual type error.** $c$ is introduced as an element of $C_0(G)$ (a 0-chain, i.e., a set of vertices), but then $\partial_1$ is applied to it — and $\partial_1$'s domain is $C_1$, not $C_0$. As written it doesn't typecheck; you'd want something like $\partial_1^*$ (a coboundary) or to define $c$ as a 1-chain on the induced edge set. The eyes-as-$b_1$ idea is cute but doesn't match the real rules either — false eyes, shape, and the two-eye rule are subtler than "rank of $H_1$ of the induced subgraph," so this is evocative rather than correct.

**§5, Benson's algorithm via Knaster–Tarski — this is the strongest section, and it's actually correct.** Unconditional life genuinely is a greatest-fixed-point computation on a monotone set operator, and this is a real, known way to think about Benson's algorithm. This part isn't just decoration — it's an accurate abstraction of an actual algorithm used in computer Go.

**§6, CGT endgames — also legitimate**, this is just restating Berlekamp–Conway–Guy/Wolfe's *Mathematical Go*, well-established territory, correctly summarized.

**§7, operator algebra — the weakest section.** The creation/annihilation operators don't encode any actual Go rule (no suicide constraint, no ko, no capture mechanics derived from anything), and the commutation relations are simply asserted to match capture behavior with zero derivation. This reads as "quantum mechanics has cool notation" rather than a structure doing real work.

**Overall verdict:** you have two genuinely solid pieces of mathematics (lattice-theoretic life/death, CGT endgames — both already exist in the literature and are correctly presented) surrounded by three sections that are essentially notation cosplay: real formalism imported without deriving Go's actual constraints from it, and in one spot (§4) with an outright type mismatch. If I were to push this toward being real math rather than an entertaining pastiche, I'd cut or heavily rework §2, §3, and §7, and instead spend more effort making §4 and §5 rigorous and maybe proving something new (e.g., an actual theorem relating $H_1$ of the stone-group subgraph to true eye count, with hypotheses on false eyes) — that's where there's real potential for a genuine result rather than an analogy.
